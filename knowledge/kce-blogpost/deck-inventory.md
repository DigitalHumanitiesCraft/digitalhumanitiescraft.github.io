## 15 AI Agent & Tool Use

Slide ID `h51448df817bc677_0_41`, status accepted.

````text
Ein AI Agent ist ein System, in dem ein LLM für ein festgelegtes Ziel Schritt für Schritt die nächste Aktion wählt, darunter Tool Use: Das Modell formuliert einen Werkzeugaufruf, etwa eine Websuche oder das Lesen einer Datei, den eine Software außerhalb des Modells ausführt. Das Ergebnis fließt in die nächste Entscheidung ein.

Prompt: Fass mir zusammen, worum es in diesem Projekt geht. 
Der Agent entscheidet selbst über die Schritte:
ls zeigt, was im Projektordner liegt. Dort gibt es einen Ordner knowledge.
cd .\knowledge\ wechselt in diesen Ordner.
ls zeigt, was dort liegt, nämlich project.md.
cat .\project.md öffnet den Text, aus dem der Agent die Zusammenfassung schreibt.
Tool Use heißt, dass der Agent selbst entscheidet, welches Werkzeug er als Nächstes einsetzt. Jedes Ergebnis bestimmt den nächsten Schritt.

Sapkota, R., Roumeliotis, K. I., & Karkee, M. (2025). AI Agents vs. Agentic AI: A Conceptual Taxonomy, Applications and Challenges. Information Fusion, 126, 103599. https://doi.org/10.1016/j.inffus.2025.103599
Xu, W., Huang, C., Gao, S., & Shang, S. (2025). LLM-Based Agents for Tool Learning: A Survey. Data Science and Engineering, 10, 533–563. https://link.springer.com/article/10.1007/s41019-025-00296-9

## 45 Model Context Protocol (MCP)

Slide ID `h2a76f1c8a73c47f4_4_905`, status accepted.

````text
MCP ist ein offener Standard, über den ein LLM an andere Programme und Datenquellen angeschlossen wird, etwa Datenbanken, Dateien oder einen Kalender. Jedes angeschlossene Programm kann über einen MCP-Server Aktionen anbieten, die das Modell auslöst, etwa eine Berechnung (Tool), Inhalte zum Lesen wie eine Dokumentation (Resource) und Vorlagen mit Anweisungen, etwa Stilregeln für Code (Prompt).

Hugging Face. Introduction to Model Context Protocol (MCP). https://huggingface.co/learn/mcp-course/unit1/introduction
Skills vs MCP vs RAG vs Memory: What AI Agents Need to Know. https://youtu.be/X4FVEEegCbk

Retrieval-Augmented Generation (RAG)

RAG gibt einem LLM Zugriff auf eigene Dokumente, etwa Word-, PowerPoint- oder Excel-Dateien, die einmal aufbereitet und in einem Suchspeicher abgelegt werden. Bei einer Frage findet das System passende Textabschnitte (Retrieval), ergänzt damit den Prompt (Augmentation), und das Modell erzeugt daraus die Antwort samt Quellen (Generation). Wie gut die Dokumente aufbereitet sind, bestimmt, wie gut die Antworten werden.

Memory

Memory gibt einem LLM ein “Gedächtnis” über einzelne Gespräche hinaus. Das System speichert selbst Notizen zu Vorlieben, Korrekturen und Vorhaben, laufend oder nach Gesprächsende. Zu Beginn lädt es ein Inhaltsverzeichnis, einzelne Notizen holt es bei Bedarf, und auf Wunsch durchsucht es frühere Gespräche. Die Notizen lassen sich einsehen, ändern und löschen. Memory wirkt als Kontext, sicher verhindern lässt sich etwas nur mit einem Hook.

Don Woodlock. What is RAG? (Retrieval Augmented Generation). https://youtu.be/u47GtXwePms
Don Woodlock. How to set up RAG – Retrieval Augmented Generation (demo). https://youtu.be/P8tOjiYEFqU

Speaker notes:

````text
Wie erkennt man, ob ein Text oder ein Bild von einer KI stammt? Eine Antwort darauf ist Watermarking, also ein unsichtbares Wasserzeichen. Bei Text und Bild funktioniert das aber ganz unterschiedlich.

Links oben sehen Sie, wie ein LLM normalerweise schreibt. Es bekommt den bisherigen Text, berechnet für jedes mögliche nächste Wort eine Wahrscheinlichkeit und zieht daraus ein Wort. Das Wort wird angehängt, und das Spiel beginnt von vorn.

Darunter sehen Sie, was sich beim Watermarking ändert. Der Anbieter hat einen geheimen Schlüssel. Aus diesem Schlüssel und den letzten Wörtern entsteht bei jedem Schritt ein Zufallswert. Dieser Zufallswert lenkt die Wortwahl ganz leicht in eine bestimmte Richtung. Der Text liest sich genauso gut, aber in der Wortwahl steckt ein statistisches Muster.

Ganz unten ist die Prüfung. Wer den Schlüssel hat, gibt einen Text hinein und bekommt einen Wert. Liegt der Wert über einer Schwelle, gilt der Text als markiert. Das funktioniert nur statistisch: Je länger der Text, desto sicherer das Ergebnis. Wer den Text umschreibt oder übersetzt, verwischt das Muster.

Rechts das Bild. Hier wird das fertige Bild markiert. Ein Encoder versteckt eine kurze Bitfolge im Bild, unsichtbar fürs Auge. Das Bild wird geteilt, als JPEG gespeichert, zugeschnitten. Ein Decoder liest die Bitfolge trotzdem wieder aus, schon bei einem einzigen Bild. Gezielte Angriffe können das Wasserzeichen aber entfernen.

Für die Praxis heißt das: Ein Wasserzeichen ist ein Hinweis, kein Beweis. Fehlt es, heißt das nicht, dass ein Mensch den Text geschrieben hat. Seit August 2026 verlangt der AI Act von Anbietern, KI-Inhalte maschinenlesbar zu kennzeichnen. Watermarks sind dafür ein Baustein.

Instead of starting from the code, I described what a researcher needed to see and why, and let the LLM generate the implementation. The data, with its semantics encoded in RDF and domain-specific ontologies, provided the structure. The user stories provided the direction. The LLM mapped one onto the other. As models improved across generations, from GPT-4 through Claude Opus 4.5 to the current frontier, the outputs grew more ambitious. What began as Python plots evolved into interactive, browser-based HTML interfaces. Tasks that failed or required extensive manual correction in 2023 worked reliably by late 2025. Informed Vibe Coding (eigener Begriff) ergänzt die Fähigkeit, Ergebnisse einzuordnen, Fehler zu erkennen und gezielt nachzubessern.
